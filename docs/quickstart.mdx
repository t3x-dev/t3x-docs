# Quick Start

Use this path when you have the source repository checked out and want to see
the product locally.

## Requirements

- Node.js 20+
- pnpm 10+
- Docker if you want the compose path
- One provider key for live extraction, generation, or chat:
  `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, or `GOOGLE_AI_STUDIO_KEY`

The core engine and YOps do not require a model provider key. The WebUI also
includes a fixture demo path, so you can inspect the interface without a key
during local development.

## Run From Source

```bash
git clone https://github.com/t3x-dev/t3x-core.git
cd t3x-core
pnpm install
pnpm dev:api
pnpm dev:webui
```

Open the URLs printed by the dev servers:

- WebUI: go to `/chat` on the WebUI URL.
- API: use the API URL printed by `pnpm dev:api`.
- API reference: append `/api/docs` to the API URL.
- OpenAPI JSON: append `/api/openapi.json` to the API URL.

In source development, the app defaults to a local developer mode. To exercise
the self-hosted login flow, start both API and WebUI with:

```bash
AUTH_DISABLED=false pnpm dev:api
AUTH_DISABLED=false pnpm dev:webui
```

## Run With Docker

```bash
docker compose up -d --build
```

Docker starts Postgres, API, and WebUI:

| Service | Default host port |
| --- | --- |
| WebUI | `3000` |
| API | `8000` |
| Postgres | `5432` |

Optional profiles:

```bash
docker compose --profile runner up -d
docker compose --profile n8n up -d
```

:::caution Self-hosting safety
Docker and self-hosted runs keep auth on by default. Do not expose a deployment
with `AUTH_DISABLED=true` to an untrusted network. Before sharing a host, review
[Deployment](./release/deployment) for auth, backups, TLS, logs, and provider
key handling.
:::

## Try The Guided WebUI Demo

Open the WebUI URL exposed by your dev server or Docker host, then go to:

```text
/chat?introDemo=1
```

The demo uses recorded fixture data. It walks through:

1. Create a project.
2. Paste or prefill source material.
3. Open Workspace.
4. Extract a staged YOps proposal.
5. Apply the YOps into a materialized tree.
6. Move to Canvas.
7. Open a Leaf output artifact.

## Shared Local Access

CLI and MCP read the same machine-local config file:

```text
~/.t3x/config.json
```

Lookup order:

```text
T3X_API_URL / T3X_API_KEY
-> ~/.t3x/config.json
-> built-in defaults
```

Useful commands:

```bash
t3x auth use-key t3xk_xxx
t3x auth status
t3x auth check
t3x config set api-url <api-base-url>/api
t3x config show
```

## Build And Check

```bash
pnpm build
pnpm test
pnpm check
```

If a test cannot resolve `@t3x-dev/*`, rebuild the lower package and its
consumers first.
