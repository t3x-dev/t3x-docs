# Canvas Workspace

The Canvas workspace is the inspection surface for committed meaning. It is
useful after you have source material, extracted knowledge, and at least one
commit. It is not the first step for most users; Chat produces reviewed commits,
then Canvas helps users inspect and reuse them.

## Version path

Canvas shows the committed semantic versions as a branch graph. Each node is a
commit that can be inspected, compared, merged, or reused as a Leaf source.

<img
  className="docScreenshot"
  src="/img/screenshots/webui-canvas.png"
  alt="T3X Canvas workspace with semantic commits, branches, and a leaf attached to a commit"
/>

What to look for:

- **Branch chips** summarize the active branches, commit count, and leaf count.
- **Commit cards** show the commit message, branch, short hash, and semantic
  tree size.
- **Version edges** show how one committed meaning state leads to another.
- **Leaf affordances** make output creation visible from the version that owns
  the knowledge.

## Commit audit

Open a commit when you need to read the exact committed meaning. The audit page
keeps the tree index, YAML view, structural graph, JSON, relations, hash chain,
and leaf links together.

<img
  className="docScreenshot"
  src="/img/screenshots/webui-commit-audit.png"
  alt="T3X Commit Audit screen with YAML tree, diff badges, hash chain, and leaf links"
/>

What to look for:

- **Tree index** on the left shows modified, added, and unchanged semantic
  nodes.
- **YAML view** is the human-readable committed tree, not raw chat text.
- **Audit rail** shows evidence, YOps operation count, hash chain, and snapshot
  metadata.
- **Top actions** let users return to Canvas, view a diff, share, or export.

## Semantic diff

Diff compares two semantic commits. It answers "what meaning changed?" rather
than only showing token-level changes in a transcript.

<img
  className="docScreenshot"
  src="/img/screenshots/webui-diff.png"
  alt="T3X semantic diff page showing modified and added YAML nodes between two commits"
/>

What to look for:

- **Base and target** hashes are fixed in the header and right rail.
- **Tree index** groups modified, added, removed, and identical nodes.
- **Split YAML** shows old meaning on the left and new meaning on the right.
- **Inline highlights** make changed slot values visible without reading the
  full tree.
- **Start Merge** creates a merge workspace from the same pair of commits.

## Merge workspace

Merge is the review surface for two branches of meaning. It separates conflicts
from auto-kept meaning and from content that exists only on one side.

<img
  className="docScreenshot"
  src="/img/screenshots/webui-merge.png"
  alt="T3X merge workspace with conflicts, auto-kept semantic nodes, source-only nodes, and merge summary"
/>

What to look for:

- **Conflict cards** place source and target slots side by side.
- **Resolution buttons** let users keep source, keep target, or keep both
  voices.
- **Auto-kept nodes** show meaning that both branches already share.
- **Source-only and target-only nodes** make branch-specific meaning explicit.
- **Merge info and voices** summarize what will enter the final merge commit.

## Commit history

History shows the semantic versions on a branch. This is where a user confirms
that a project has moved from initial extracted meaning to a later reviewed
state.

<img
  className="docScreenshot"
  src="/img/screenshots/webui-history.png"
  alt="T3X commit history screen with two commits on main"
/>

The history view should answer three questions quickly:

- Which branch is this version on?
- Which commit is the current head?
- What changed at a human-readable level?

## Leaf output

Leaves are reusable artifacts generated from a commit. They keep constraints and
assertions next to the output so the user can see whether the artifact preserved
the committed meaning.

<img
  className="docScreenshot"
  src="/img/screenshots/webui-leaf.png"
  alt="T3X Leaf output screen with source frames, generated checklist, constraints, and assertions"
/>

What to look for:

- **Source frames** on the left show the semantic content available to the
  output.
- **Output** in the center is the generated artifact.
- **Review stack** on the right shows semantic coverage, constraints, and
  assertion results.
- **Commit verified** and assertion badges make the output's state visible
  without reading every line.

## When to use Canvas

Use Canvas after a commit exists and the user needs to inspect, compare, or
reuse that version. Use Chat when the user is still adding source material or
reviewing pending extraction.
