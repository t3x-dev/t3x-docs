# WebUI Overview

The T3X WebUI is the product surface for reviewing meaning before it becomes a
semantic commit. It is intentionally not a generic chatbot skin: Chat is where
source material enters, Workspace is where YOps and extracted meaning are
reviewed, Canvas is where committed versions are inspected, and Leaf is where
committed knowledge becomes an output artifact.

## Start the WebUI

:::caution v0.3.0 publish pending
The packaged local command becomes available after the v0.3.0 npm publish
completes. Use the source-development commands below when contributing from the
repository.
:::

For the packaged local alpha:

```bash
npx -p @t3x-dev/local t3x-local start
```

For source development:

```bash
pnpm dev:api
pnpm dev:webui
```

Open `http://localhost:3000`.

## Product loop

```text
Source -> Meaning -> Commit -> Leaf
```

1. **Source** keeps the original prompt, transcript, release note, or design
   discussion visible.
2. **Meaning** is reviewed through the proposed YOps operations and the
   materialized tree before commit.
3. **Commit** stores reviewed meaning as a durable semantic version.
4. **Leaf** turns that committed meaning into an output with constraints and
   validation.

## Screenshot guide

The WebUI pages use a small screenshot set from the bundled demo fixture. Use
them to explain the product in this order:

| Screenshot | Use it to explain |
| --- | --- |
| Chat intake | T3X starts from raw source material, not from a hand-written schema. |
| Chat review and YOps | Extraction is reviewable before commit. |
| Canvas version path | Branches, commits, and leaf affordances live on one semantic graph. |
| Commit audit | A semantic version can be audited by tree, YAML, JSON, hash chain, and relations. |
| Semantic diff | Base and target commits are compared as meaning, with modified and added nodes called out. |
| Merge workspace | Conflicts, auto-kept meaning, and branch-only additions are resolved before a merge commit. |
| Commit history | A branch has semantic commits, not only raw chat logs. |
| Leaf output | Outputs are tied back to committed meaning and checked by constraints. |
