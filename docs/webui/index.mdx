# WebUI Overview

The WebUI is the T3X workbench. It starts like a chat surface, but the value is
what happens after the first reply: source becomes YOps, YOps become a reviewed
tree, the tree becomes a commit, and commits become reusable output artifacts.

```bash
pnpm dev:api
pnpm dev:webui
```

Open `http://localhost:3000/chat`.

![Chat landing](/img/screenshots/chat-light.png)

## Core Workflow

| Step | User sees | Value |
| --- | --- | --- |
| Chat | A lightweight place to paste a prompt, transcript, release note, or design discussion | Keeps the original source text instead of losing it in a generated answer |
| Workspace | A right-side YOps editor and output panel | Makes extraction reviewable before project state changes |
| Staged YOps | Pending YAML operations plus a dry-run output tree | Lets users inspect what the LLM proposed before Apply |
| Applied YOps | Materialized operation count and semantic tree | Confirms the deterministic engine produced stable structure |
| Canvas | Version graph with commit cards, branches, leaves, and pending work | Shows where meaning lives across project history |
| Leaf | Source-backed output artifact with constraints and assertions | Turns committed meaning into reusable work: checklist, article, prompt, eval, agent config |

## 1. Chat: Start From Source

![Chat demo composer](/img/screenshots/webui-03-demo-composer.png)

Chat is intentionally low-friction. Users paste the material they want T3X to
make sense of. The source may be a prompt version, support note, meeting note,
release plan, design discussion, or agent trace.

Value produced:

- Keeps the original source available.
- Creates the first conversation context.
- Gives users a natural path into extraction instead of asking them to model a
  tree by hand.

## 2. Workspace: Review The Mutation

![Workspace empty](/img/screenshots/webui-05-yops-workspace-empty.png)

Workspace is the precision surface. The left side remains conversational; the
right side shows the mutation machinery.

Value produced:

- Separates natural-language discussion from structured state.
- Keeps the YOps proposal visible.
- Gives the user a place to apply, discard, continue editing, or commit.

## 3. Staged YOps: See The Proposal

![YOps staged](/img/screenshots/webui-06-yops-staged.png)

After Extract, T3X shows a pending proposal. This is where the user should ask:
"Is this what we want the project to remember?"

Value produced:

- Prevents silent mutation by model output.
- Shows the exact YAML operations.
- Shows the dry-run tree before it becomes materialized state.

## 4. Applied YOps: Materialize Meaning

![YOps applied](/img/screenshots/webui-07-yops-applied.png)

Apply runs the deterministic engine. The screenshot shows the important state:
materialized operations, pending count, source-backed rows, and the output tree.

Value produced:

- Confirms the proposal is no longer merely a draft.
- Produces a stable tree that can be committed.
- Preserves the operation log for audit.

## 5. Canvas: Inspect Semantic Versions

![Canvas selected](/img/screenshots/webui-09-canvas-selected.png)

Canvas is not a decorative graph. It is the project version path: commits,
branches, leaves, and pending work.

Value produced:

- Makes semantic history visible.
- Shows which output leaves came from which commit.
- Helps users inspect source, diff, leaves, and next actions from a selected
  version.

## 6. Leaf: Turn Commits Into Output

![Leaf detail](/img/screenshots/webui-12-leaf-detail.png)

Leaf is where committed meaning becomes a reusable artifact. A leaf has its own
constraints, generated output, source coverage, quality checks, and export
actions.

Value produced:

- Keeps output tied to a commit hash.
- Shows which semantic points were included.
- Tracks assertions and constraints separately from the commit itself.
- Lets users retune output without mutating the underlying commit.
