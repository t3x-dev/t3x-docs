# Operation Board

This board gives one concrete example for each YOps operation. The examples use
the same support-escalation tree from the overview.

## DDL: Structure

| Op | Use it when | Example |
| --- | --- | --- |
| `define` | Create a new mapping path | `define: { path: support_escalation_review/refund_policy }` |
| `drop` | Remove a node or subtree | `drop: { path: support_escalation_review/legacy_copy }` |
| `rename` | Rename a key without rewriting the subtree | `rename: { path: support_escalation_review/refund_policy, to: escalation_policy }` |

## DML: Values

| Op | Use it when | Example |
| --- | --- | --- |
| `set` | Set one scalar, list, or mapping value | `set: { path: support_escalation_review/rollout, value: pilot on Friday }` |
| `unset` | Remove one key but keep the parent | `unset: { path: support_escalation_review/refund_policy/draft_note }` |
| `populate` | Fill several fields on the same mapping | `populate: { path: support_escalation_review, values: { audience: customer support team, objective: tighten refund escalation } }` |
| `append` | Add one item to a sequence | `append: { path: support_escalation_review/refund_policy/required_evidence, value: agent name }` |

## DTL: Reshape

| Op | Use it when | Example |
| --- | --- | --- |
| `move` | Relocate a subtree | `move: { from: support_escalation_review/tone, to: support_escalation_review/tone_and_safety/tone }` |
| `clone` | Copy an existing subtree | `clone: { from: support_escalation_review/refund_policy, to: support_escalation_review/qa_policy }` |
| `nest` | Group sibling keys under a new wrapper | `nest: { path: support_escalation_review, keys: [tone, avoid], under: tone_and_safety }` |
| `split` | Split one mapping into named children | `split: { path: support_escalation_review, into: { refund_policy: [threshold, required_evidence], tone_and_safety: [tone, avoid] } }` |
| `fold` | Collapse a single-child wrapper | `fold: { path: support_escalation_review/wrapper }` |
| `merge` | Combine sibling mappings | `merge: { path: support_escalation_review, keys: [refund_policy, qa_policy], into: review_policy }` |
| `sort` | Sort a sequence | `sort: { path: support_escalation_review/refund_policy/required_evidence }` |
| `unique` | Deduplicate a sequence | `unique: { path: support_escalation_review/refund_policy/required_evidence }` |
| `pick` | Keep only specific keys | `pick: { path: support_escalation_review/refund_policy, keys: [threshold, required_evidence] }` |
| `omit` | Remove specific keys | `omit: { path: support_escalation_review/refund_policy, keys: [temporary_note] }` |

## DCL: Check

| Op | Use it when | Example |
| --- | --- | --- |
| `assert` | Verify state without changing it | `assert: { path: support_escalation_review/refund_policy/threshold, equals: Refunds above $100 require manual review }` |

## How To Read The Board

Use DDL when the shape is wrong. Use DML when the values are wrong. Use DTL when
the information is present but arranged badly. Use DCL when you need a guardrail
before later operations continue.

```yaml
yops:
  - assert:
      path: support_escalation_review/refund_policy/threshold
      equals: Refunds above $100 require manual review
  - append:
      path: support_escalation_review/refund_policy/required_evidence
      value: agent name
  - unique:
      path: support_escalation_review/refund_policy/required_evidence
```

This sequence says: first prove the current threshold is the one we expect, then
add a new required evidence field, then dedupe the list.
